# Orbit Video — WebRTC video calling demo

A two-person browser video call app using WebRTC for peer-to-peer audio/video and a small WebSocket server for signaling.

## Run locally

1. Install Node.js 18 or newer.
2. In this folder, run:

   ```bash
   npm install
   npm start
   ```

3. Open http://localhost:3000 in a modern browser.
4. Click **Create room**, allow camera/microphone access, then copy the invite link.
5. Open the link in another browser/device and click **Join room**.

For local testing on the same computer, use two browser windows or profiles. For testing on another device on your LAN, use the host computer's LAN IP, but camera/microphone access generally requires HTTPS (localhost is the exception).

## Deploy publicly

Deploy the Node app to a host that supports long-lived WebSocket connections. Put it behind HTTPS so the page uses secure WebSockets (`wss://`). Camera and microphone access require a secure context (HTTPS or localhost).

## TURN server for reliable connectivity

The demo includes public Google STUN servers. STUN alone cannot connect every pair of networks. For production, add your own TURN service (for example, coturn) to the `iceServers` array in `public/index.html`:

```js
{
  urls: 'turn:turn.example.com:3478',
  username: 'TURN_USERNAME',
  credential: 'TURN_PASSWORD'
}
```

Do not expose permanent TURN credentials in public client-side code; use short-lived credentials generated by your backend.

## Limitations and security

- Two participants per room; no accounts, recording, chat, or end-to-end identity verification.
- The signaling server relays connection setup messages, not the video/audio stream.
- Anyone who knows a room ID can attempt to join. Use random room IDs and add authentication/authorization before production use.
- Serve only over HTTPS in production.


## Deploy frontend on GitHub Pages + signaling server on Render

1. Upload the root `index.html` to the root of a GitHub repository.
2. In `index.html`, replace `wss://YOUR-RENDER-SERVICE.onrender.com` with your actual Render service hostname, using `wss://`.
3. Enable GitHub Pages in the repository: Settings → Pages → Deploy from a branch → `main` → `/ (root)`.
4. Deploy this same repository to Render as a **Web Service**:
   - Build command: `npm install`
   - Start command: `npm start`
5. Copy the Render service hostname into `SIGNALING_SERVER` in `index.html`, commit, and push again.

GitHub Pages hosts the static frontend. Render runs the Node.js WebSocket signaling server. WebRTC carries media peer-to-peer. Use HTTPS on the Pages site and WSS for signaling. Configure TURN for reliable connectivity on restrictive networks.
